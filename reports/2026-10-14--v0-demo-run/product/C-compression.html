C · How much smaller the change gets

The project's headline claim: the text diff a reviewer reads today (the denominator, from cppsd plan) against the change events cppsd diff reports (the numerator). Lines and change events are different units, so they are never drawn on the same axis. The ratio connects them. New in schema 2.0: the changed C++ lines that no change event explains (ADR-042).

Which kinds of change event make up the total

Every change event in each document, by kind. The colour follows the kind on both repositories. Hover a segment for its count. NodeSignatureChanged, NodeAttrChanged and CallerOfChangedSignature did not occur in run B.

Changed lines no change event explains

A changed token is explained when a change event's hunk covers its line (ADR-042). Line granularity, so the count is a lower bound. Files are listed by uncovered tokens, the most first.

Read with care

Lines per change event is not a quality score. It goes up when more of the change is outside what was modelled. spdlog's compile database has 8 translation units against 95 changed C++ files. Of spdlog's uncovered lines, the tool puts about in files no model declares anything in.

High-risk is computed from impact, not the ranking total, and since ADR-046 never counts a change of spelling only. Page D shows both.

Top-level means a change event with no caused_by; the others are nested under a cause (ARCH-001 §6.3).
